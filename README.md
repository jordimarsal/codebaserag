# codebaserag

Hexagonal RAG over your own codebase, with a deterministic, eval-first core.

## Stack

Python 3.13 · Pydantic v2 · typer · FastAPI · pgvector (default) / Qdrant · Ollama /
Anthropic embeddings & LLM · Langfuse observability. Tooling: `ruff`, `black`, `mypy --strict`,
`pytest`.

## Install (one command)

```bash
CODERAG_REF=v0.1.1 curl -LsSf https://raw.githubusercontent.com/jordimarsal/codebaserag/v0.1.1/install.sh | sh
```

Both the installer and the package source are pinned to the `v0.1.1` ref above — prefer a
pinned ref over `main` so the code you run is always a reviewed release (audit finding
`install-sh-curlsh-unpinned-git-main-bootstrap`).

This installs [`uv`](https://docs.astral.sh/uv/) if it is not present (uv fetches Python 3.13 on
its own — you do not need Python), then `uv tool install`s `coderag` in an isolated environment
with the `pgvector,embeddings,llm,qdrant` extras. Override with `CODERAG_EXTRAS="..."` (or
`CODERAG_EXTRAS=""` for a minimal install: memory store + fake LLM still work). Re-running the
same command re-installs that ref; to update, bump `CODERAG_REF` to the newer tag.

```bash
coderag query "how does chunking work" --store memory --repo .   # offline, no services
coderag ingest <repo>                                            # needs pgvector/qdrant + an embedder
```

Manual equivalent: `uv tool install --from "codebaserag[pgvector,embeddings,llm,qdrant] @ git+https://github.com/jordimarsal/codebaserag@v0.1.1" coderag`

## Commands

```bash
uv run coderag ingest <repo>          # index a repo into the vector store
uv run coderag query "..."           # naive top-k retrieval (no generation yet)
uv run coderag eval --store memory   # run the deterministic retrieval eval (offline)
uv run coderag eval --update-baseline  # refresh evals/baseline.json
```

## Architecture

Hexagonal: a pure core (chunking, RRF fusion, prompt assembly, citations) depends only on
`Protocol` ports (`VectorStore`, `Embedder`, `LlmClient`, `Reranker`). Adapters
(pgvector, Qdrant, Ollama, Anthropic, OpenAI) implement those ports without touching the
core. See `docs/architecture.md` and `docs/conventions.md`.

## API (FastAPI)

`uv run coderag serve` starts a uvicorn server that composes ingest + hybrid retrieval +
structured generation. Backend/strategy/LLM are configured via `CODERAG_*` env
(`CODERAG_VECTOR_STORE`, `CODERAG_RETRIEVAL_STRATEGY`, `CODERAG_LLM_BACKEND`, ...).

| Method | Path | Body | Purpose |
|--------|------|------|---------|
| POST | `/ingest` | `{"repo": "."}` | Index a repo into the configured store. |
| POST | `/query` | `{"question", "top_k?", "strategy?"}` | Top-k retrieved chunks (matches the core `Retriever`). |
| POST | `/answer` | `{"question", "top_k?", "strategy?"}` | Grounded `Answer` with citations (schema-constrained generation). |

The retrieval path is the eval-suite contract: `POST /query` returns the same chunk set as the
core `Retriever` for the same question. Offline: `CODERAG_VECTOR_STORE=memory
CODERAG_LLM_BACKEND=fake uv run coderag serve`.

## Run with Docker

```bash
cp .env.example .env        # adjust secrets / Ollama + LLM endpoints
docker compose up           # postgres/pgvector + API (ingests /repo, serves :8000)

# optional observability + alternate store:
docker compose --profile langfuse up   # adds self-hosted Langfuse (set CODERAG_OBSERVABILITY_BACKEND=langfuse)
docker compose --profile qdrant up     # adds a Qdrant store (set CODERAG_VECTOR_STORE=qdrant)
```

The image runs `coderag ingest /repo` then serves the API. Embeddings/LLM must be reachable from the
container (e.g. a host Ollama at `host.docker.internal:11434`, or set `CODERAG_LLM_BACKEND`/`EMBEDDER_URL`).

**Embedding backend.** Set `CODERAG_EMBEDDER_BACKEND=ollama` (default) or `llamacpp`. The `llamacpp`
backend targets a llama.cpp server's OpenAI-compatible `/v1/embeddings` endpoint — point
`CODERAG_EMBEDDER_URL` at it (default `http://localhost:8080`). This lets you serve embeddings from the
same llama.cpp build with no Ollama dependency.

## Local dev with llama.cpp (embeddings, no Ollama)

`scripts/start-llamacpp.sh` launches a llama.cpp server with `--embeddings` enabled. It needs an
**embedding** model (LLMs won't serve `/v1/embeddings`); `nomic-embed-text-v1.5` matches the default
`CODERAG_EMBEDDER_MODEL`.

```bash
# 1) start the embedder (download an embedding model first if needed)
LLAMACPP_MODEL=/home/jordi/ia/llama/models/nomic-embed-text-v1.5.Q4_K_M.gguf \
  LLAMACPP_GPU=99 LLAMACPP_BATCH=2048 \
  bash scripts/start-llamacpp.sh          # listens on :8080, logs to /tmp/llamacpp-server.log

# 2) start the vector store(s)
docker compose up -d db                   # postgres/pgvector on :5432
docker compose --profile qdrant up -d     # (optional) Qdrant on :6333

# 3) index this repo and refresh the eval baseline
export CODERAG_DATABASE_DSN=postgresql://coderag:coderag@localhost:5432/coderag
uv run coderag ingest . --store pgvector
uv run coderag eval  --store pgvector --update-baseline

# 4) stop everything
pkill -f llama-server
docker compose stop db qdrant
```

Notes:
- `CODERAG_EMBEDDER_BACKEND=llamacpp` (set in `.env`) makes `ingest`/`query`/`answer` use the server.
- `LLAMACPP_BATCH` (default 2048) must cover your longest chunk; llama.cpp 500s on inputs over its
  2048-token context. `LlamaCppEmbedder` guards this client-side (`max_chars`, with a 500-retry).
- `qdrant-client` is an optional extra: `uv pip install qdrant-client` before using `--store qdrant`.
